# Захват в инбокс

Инбокс — сырой поток за неделю, общий на все пять областей знаний (Kotlin,
Compose, Android, Architecture, Portfolio). Большая часть его содержимого
будет удалена при сортировке, поэтому запись должна стоить пять секунд и ноль
решений.

Хаб — репозиторий `pool-digest`, доска `Knowledge Union` (`gh project` номер
8, владелец берётся из `gh repo view` текущего репозитория, если он в той же
организации, иначе `akopyan757`). Элемент — issue с меткой `inbox`, не файл:
так к инбоксу можно писать из любого репозитория и с бота, а разбор виден на
доске, а не только в файле.

## Запись

**Не задавай вопросов.** Ни про тему, ни про важность, ни про то, лист это или
факт. Любой уточняющий вопрос при захвате убивает привычку — вся сортировка
происходит потом, отдельно.

```bash
gh issue create -R akopyan757/pool-digest \
  --title "<первые 80 символов текста>" \
  --body "<текст как есть>" \
  --label inbox
```

Дальше — на доску, статус `Inbox` (он и так дефолт первой опции, но выставить
явно надёжнее), поле `area` — лучшая догадка по ключевым словам, не более:

```bash
gh project item-add 8 --owner akopyan757 --url <issue-url>
gh project item-edit 8 --owner akopyan757 --url <issue-url> \
  --field "Status" --value "Inbox"
gh project item-edit 8 --owner akopyan757 --url <issue-url> \
  --field "area" --value "<Kotlin|Compose|Android|Architecture|Portfolio|?>"
```

Догадка про область — по ключевым словам в тексте, первое совпадение
побеждает, ничего не совпало — `?`:

| Область | Ключевые слова |
|---|---|
| Kotlin | kotlin, coroutine, corout, suspend, flow, sealed, inline, generic, kotlinlang |
| Compose | compose, recomposition, composable, slot table, modifier |
| Android | android, activity, service, manifest, zygote, binder, intent, permission |
| Architecture | архитектур, mvvm, mvi, clean architecture, ssot, модуляризац, dagger, hilt, koin, di |
| Portfolio | портфел, sharpe, дохо́дност, risk, drawdown, rebalanc, дивиденд, var, cvar |

Правила записи:

- если пользователь дал ссылку без комментария — запиши ссылку как есть и
  попроси в одну строку добавить, зачем она (но запись уже сделана, не
  блокируй её вопросом)
- если дал только мысль без ссылки — записывай как есть
- не переформулируй, не улучшай, не расширяй. Слова пользователя — это его
  будущий поисковый запрос
- не добавляй теги, приоритеты, эмодзи сверх метки `inbox` и поля `area`
- несколько элементов в одном сообщении — несколько issue

Подтверждай коротко: «записал» и всё. Не пересказывай, что записал, не
показывай номер issue, если не спросили.

## Показать инбокс

По запросу «что в инбоксе» — список открытых issue с меткой `inbox` и
статусом `Inbox` на доске:

```bash
gh issue list -R akopyan757/pool-digest --label inbox --state open
```

Выведи как есть, с общим числом. Ничего не сортируй и не группируй по смыслу:
пользователь сам решает при разборе (скилл inbox-sorting).

Если элементов больше 25 — скажи об этом отдельной строкой: значит, разбор
пропускался, и стоит его провести.
