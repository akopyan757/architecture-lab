🏗️ State читают, effect выполняют state / event / one-time effect: почему effect не живёт в state Состояние, событие и одноразовый эффект различаются не типом данных, а тем, что случится, если сообщение прочитать дважды. Состояние отрисуется тем же экраном, эффект выполнится второй раз — и это единственная причина, почему команде не место в state.
Самый частый случай — snackbar «Сохранено» полем в state. Работает ровно до первого события, которое заставит UI прочитать state ещё раз. Поворот экрана, возврат из бэкстека, рекомпозиция — новый подписчик получает последнее значение, в котором лежит команда, и snackbar показывается второй раз. Это не баг Compose или StateFlow: они делают ровно то, для чего созданы. Вторая поломка — склейка. Две ошибки подряд между двумя чтениями UI: второе значение перезаписало первое, показалось одно сообщение. State хранит последнее значение, а не историю — для данных это правильно, для команд это потеря. Обе поломки одной природы: effect требует «одна запись — одно выполнение», а state гарантирует только «последнее значение доступно всегда». Разные контракты. Практический тест: isLoading = true после поворота всё ещё правда, загрузка идёт. «Сохранено» после поворота уже не правда, сохранение случилось один раз в прошлом. Если значение может протухнуть само, без нового события, — это не state. Два честных выхода. Первый — оставить в state, но сделать состоянием: «есть непоказанное сообщение» плюс явный сброс после показа. Это позиция гайда Android по UI events. Платишь ручным циклом потребления, окном гонки между показом и сбросом и одним слотом на сообщение. Второй — отдельный канал рядом со state: каждый элемент доставляется одному получателю один раз, повтора и склейки нет по построению. Платишь потерей без подписчика, невозможностью пережить смерть процесса и вторым потоком из ViewModel, порядок между которыми не гарантирован. Критерий выбора — один вопрос к каждому эффекту: можно ли переформулировать его как факт про экран так, чтобы повторное чтение ничего не требовало делать? «Открой главный после логина» — это «пользователь авторизован», и поворот в момент завершения логина перестаёт быть проблемой: факт истинен или ложен, одноразовым он не бывает. «Покажи ошибку» — это «загрузка завершилась ошибкой». А «вибрируй» или «открой share sheet» переформулировать нечем — это effect, и ему нужен канал.
