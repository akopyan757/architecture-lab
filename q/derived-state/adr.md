# ADR: производное поле в state — вычислять, хранить только как кэш с ключом

## Контекст
Экранное состояние содержит значения, выводимые из других полей того же состояния
(сумма корзины из `items`, `fullName` из `first`/`last`, отфильтрованный список из
`items` и `query`). Вопрос: класть их отдельным полем или вычислять на чтении.

## Варианты
- A. Поле в state, каждый писатель пересчитывает сам.
- B. Поле в state, все переходы через один редьюсер.
- C. Вычисление на чтении (`get()`), второго слота нет.
- D. Кэш с ключом (`remember(key)`, `derivedStateOf`, `combine` + `stateIn`), когда
  вычисление дорого и читается много чаще, чем меняется источник.

## Выбор
C по умолчанию. D, если по замеру стоимость × частота чтений заметно выше частоты
изменения источника. A и B не выбираются: стенд `derived.kt` показывает расхождение
в A на втором шаге (новый писатель), в B на четвёртом (новая ветка без пересчёта) и
пятом (`copy()` мимо редьюсера).

## Предпосылки, которые можно перепроверить
- Значение — чистая функция от текущих полей state. Если нет (снимок на момент,
  случайность, ответ другого процесса), это не производное, а свой источник истины,
  и его хранят.
- Ключ кэша перечисляет все источники и сравнивается по значению. Неполный ключ
  (`remember(query)` без `items`) или ключ по ссылке (`ByteArray`) возвращают
  рассинхрон.
- Стоимость вычисления замерена, а не предположена: сумма 20 позиций на три чтения
  в кадр не повод для кэша.
